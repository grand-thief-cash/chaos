## 0. 执行摘要

Chaos 风险智能平台的目标不是预测所有崩盘、保证逃顶或直接产生买卖指令，而是持续回答：

1. 截至某个明确的数据截止时间，市场、行业、个股或组合当前处于多高风险；
2. 未来 1、5、20、60 个交易日分别可能发生什么风险；
3. 风险来自国内市场、全球市场、行业周期、估值拥挤、公司基本面，还是外部事件和供应链；
4. 每项判断的概率、严重程度、置信度、数据质量和证据是什么；
5. 数据不足、关系失效或模型超出适用范围时，系统是否能够明确输出 `DEGRADED` 或 `UNKNOWN`，而不是伪造安全结论。

风险系统与投资策略严格解耦：

- 风险系统输出风险事实、概率、严重程度、置信度和原因；
- 风险系统不输出 `BUY`、`SELL`、目标仓位、止盈止损或做 T 指令；
- 持有多久、何时减仓、是否离场由未来独立的策略或人工决策使用风险结果后决定；
- 本文不建设交易执行、券商下单或自动持仓调整能力。

本计划采用严格串行的阶段门禁：

```text
Phase 0 核心数据修复与风险数据蓄水
  → Phase 1 国内市场风险基线
  → Phase 2 全球市场传导
  → Phase 3 A股科技子行业风险
  → Phase 4 统计/机器学习校准
  → Phase 5 Atlas 事件与供应链影响
  → Phase 6 个股综合风险
  → Phase 7 组合风险聚合
  → Phase 8 生产影子运行与持续治理
```

每个阶段必须：

1. 完成该阶段的数据、服务、测试、可视化和验收报告；
2. 满足进入下一阶段的硬门槛；
3. 由用户明确确认阶段完成；
4. 才能开始下一阶段的功能实现。

唯一的跨阶段例外是**原始数据蓄水**：全球行情、公告、新闻、政策和其他只提供近期数据的来源，应从 Phase 0 起保存带时间戳的原始快照。提前采集不代表提前实现后续分析能力，而是为了防止未来没有可回测历史。

## 1. 核心架构决策

### 1.1 产品定位

本系统定位为：

> Chaos Risk Intelligence Platform 是独立于投资策略的、多主体、多期限、可校准、可解释、可追溯的风险度量平台。

它首先服务于风险认知，未来可以被以下消费者使用：

- Cthulhu 风险驾驶舱；
- 人工投资决策；
- 研究和回测；
- 未来的选股、择时、仓位或策略服务；
- 风险通知和运营监控；
- Atlas 的事件影响解释。

### 1.2 拟新增独立风险服务

建议新增独立服务，暂称：

```text
Aegis
```

`Aegis` 只是工作名称，正式实施 Phase 1 前可重新命名。

Aegis 负责：

- 风险标签与风险事件定义；
- 国内、全球、行业、个股、组合的风险评估；
- 规则、统计模型和机器学习模型的组合；
- 风险概率与置信度校准；
- 风险驱动贡献和解释；
- 历史评估、样本外验证、基线比较和模型晋级；
- 风险评估结果的版本化写入。

Aegis 不负责：

- 下载原始行情、财务、公告、新闻或研报；
- 直接连接 PostgreSQL 或 Neo4j；
- 维护产业链知识图谱；
- 计算所有通用 Feature；
- 产生交易指令；
- 连接券商或修改持仓。

### 1.3 多期限而非预设持有周期

风险平台不要求用户提前提供固定持有时长。统一输出以下风险期限：

| Horizon | 含义 | 初始用途 |
|---|---|---|
| `1d` | 隔夜至下一交易日 | 短期跳空、隔夜外部冲击 |
| `5d` | 约一周 | 短期风险扩张和市场传染 |
| `20d` | 约一月 | 主要回撤和板块退潮风险 |
| `60d` | 约一季 | 中期估值、盈利和产业周期风险 |

不同期限必须分别评估，不允许把一个“综合风险分”复制到所有期限。

### 1.4 两类固定风险快照

日频系统至少生成两类快照：

| 快照 | 数据截止时间 | 允许使用的数据 | 回答的问题 |
|---|---|---|---|
| `PRE_OPEN` | A股开盘前的明确时间点 | 已结束的隔夜市场、上一交易日国内/亚洲市场、盘前公告 | 今天开盘前风险如何 |
| `POST_CLOSE` | A股收盘后的明确时间点 | 当日A股、已结束的亚洲市场、截至截止时间的公告与宏观数据 | 收盘后未来风险如何变化 |

将来若增加盘中风险，必须作为独立阶段定义，不得复用盘后数据。

### 1.5 风险结果不是单一分数

风险评估的逻辑契约至少包含：

| 字段族 | 关键内容 |
|---|---|
| 主体 | `subject_type`、`subject_id`、主体版本 |
| 时间 | `as_of_time`、`data_cutoff_time`、交易时段、时区 |
| 期限 | `1d`、`5d`、`20d`、`60d` |
| 风险类型 | 回撤、波动扩张、流动性、相关性传染、相对跑输、事件供应链等 |
| 度量 | 概率、严重程度、历史分位、区间而非伪精确点值 |
| 质量 | 置信度、数据完整度、新鲜度、适用域状态 |
| 解释 | Top Drivers、方向、贡献度、证据引用 |
| 血缘 | Feature 版本、规则/模型版本、代码版本、数据快照 |
| 状态 | `VALID`、`DEGRADED`、`UNKNOWN`、`INVALID` |

风险结果中明确禁止出现：

- `buy`、`sell`；
- 建议仓位；
- 目标价格；
- 保证收益或保证避险；
- 无证据的自然语言结论。

### 1.6 主体模型必须逐步扩展

当前 Feature Platform 只能执行 `security`，PhoenixA 数值物化也限定证券主体；当前 PhoenixA Feature Provider 只支持 `financial_statement`。

风险路线需要按阶段增加类型化主体：

```text
market  →  sector  →  security  →  portfolio
```

不把市场或行业结果复制到每一只证券上，也不立即建设含义模糊的万能 Entity 表。每次新增主体类型前，必须评审：

- 稳定身份；
- 生命周期；
- 时间语义；
- 物化方式；
- 查询和权限；
- 与现有 `security_id` 的关系。

### 1.7 先建立基线，再证明复杂模型的增量价值

模型演进顺序固定为：

```text
稳健统计/历史分位
  → 可解释规则基线
  → 异常和变化点
  → 可校准的传统机器学习
  → 事件/供应链增量
  → 必要时才评估更复杂模型
```

第一轮不采用强化学习。强化学习若未来存在价值，也只在可靠风险状态和离线仿真成熟后评估风险预算问题，不用于最初的危机识别。

### 2.1 已存在的可利用能力

- Feature Platform 版本、依赖、PIT、回填、运行恢复和血缘基础设施；
- 东方财富研报下载任务；

Cthulhu 已有：

- Feature Platform 治理和运行页面；
- Atlas 治理、抽取、实体和图谱页面；
- 行情与财务数据展示基础。

### 2.2 尚不能视为已完成的能力

以下内容不得从代码存在推断为生产可用：

- PhoenixA 实际数据量、历史覆盖和连续性；
- 当前 Feature Platform 的市场/行业 Feature；
- 可用于研究的真实业务 Feature；
- Atlas Event、CanonicalEvent、EventRevision；
- Atlas Impact Engine；
- 全球市场稳定数据源；
- 历史新闻和公告的不可变快照；
- 风险标签、风险模型、风险 API；
- 组合持仓和券商账户；
- 生产环境风险计算和告警。

### 2.3 已知数据风险

现有下载代码中存在将缺失或非法数值转换为 `0.0` 的路径。风险系统实施前必须区分：

- 真实值为零；
- 原始来源为空；
- 解析失败；
- 不适用；
- 无穷或非法值；
- 数据尚未发布。

任何未标记的缺失值填零，都可能把“未知风险”错误转换成“低风险”。

## 3. 目标架构与服务边界

### 3.1 总体数据流

```text
外部数据源
   │
   ▼
Artemis ────────────────► MinIO
采集/校验/原始快照          原始文档、响应、模型制品
   │
   ▼
PhoenixA
ODS + 治理 + Feature + Risk 统一数据/API 网关
   │
   ├──────────────► Artemis Feature Platform
   │                 PIT Feature 计算与物化
   │                         │
   │                         ▼
   │                      PhoenixA
   │
   ├──────────────► Atlas
   │                 Claim、实体、事件、供应链影响
   │                         │
   │                         ▼
   │                      PhoenixA / Neo4j
   │
   └──────────────► Aegis
                     风险标签、规则、模型、评估、解释
                             │
                             ▼
                          PhoenixA
                             │
             ┌───────────────┴───────────────┐
             ▼                               ▼
          Cthulhu                         Cronjob
       展示/诊断/验收                调度/重试/依赖编排
```

### 3.2 服务职责矩阵

| 服务 | 拥有的职责 | 明确不拥有的职责 |
|---|---|---|
| **Artemis** | 外部数据接入、原始快照、质量预检、Feature 计算、Feature 回填 | 风险模型决策、投资策略、交易执行 |
| **PhoenixA** | 数据持久化、Schema、治理、统一 CRUD/API、版本和血缘查询 | 复杂风险计算、LLM 抽取、交易逻辑 |
| **Feature Platform** | 可复用确定性 Feature、PIT 依赖、版本、运行与物化 | 最终风险概率、风险模型晋级、自然语言结论 |
| **Aegis** | 风险标签、风险事件、规则/模型、校准、评估、解释和风险结果 | 原始数据下载、图谱维护、下单、持仓修改 |
| **Atlas** | Claim、实体、事件、产业链和影响路径、证据 | 最终市场风险概率、交易建议、任意数据库直连 |
| **Cronjob** | 调度、阶段依赖、重试、超时、任务状态 | 业务算法、数据解释 |
| **Cthulhu** | 风险驾驶舱、历史、解释、数据质量、验收与治理 UI | 在浏览器端计算权威风险、隐藏后端错误 |
| **MinIO** | 原始文件、原始响应、不可变证据、模型制品 | 结构化查询和业务状态 |
| **Neo4j** | Atlas 图谱投影和关系查询 | 风险结果权威存储、市场时序计算 |

### 3.3 服务间契约原则

1. Artemis、Atlas、Aegis 不直接连接 PhoenixA 所管理的 PostgreSQL；
2. 风险输入必须引用已发布 Feature 版本或已治理的数据字段；
3. Aegis 写入的风险结果必须带完整数据截止时间和版本血缘；
4. Atlas 只提供事件/供应链影响输入，不直接决定最终风险等级；
5. Cthulhu 不在前端补算或猜测缺失结果；
6. Cronjob 只编排已经由各服务提供的幂等任务；
7. 任一依赖失败时，下游必须 `DEGRADED/UNKNOWN`，不得默认沿用为低风险。

## 4. 风险定义与验证原则

### 4.1 初始风险类型

| 风险类型 | 主体 | 初始定义方向 |
|---|---|---|
| `DRAWDOWN` | 市场、行业、证券、组合 | 未来期限内最大回撤 |
| `VOLATILITY_EXPANSION` | 市场、行业、证券 | 短期波动率相对长期显著扩张 |
| `CORRELATION_CONTAGION` | 市场、行业、组合 | 相关性上升导致分散失效 |
| `LIQUIDITY_STRESS` | 市场、行业、证券、组合 | 成交、价差、可退出能力恶化 |
| `RELATIVE_UNDERPERFORMANCE` | 行业、证券 | 相对基准显著跑输 |
| `VALUATION_COMPRESSION` | 行业、证券 | 高估值遇到增长或流动性恶化 |
| `EVENT_SUPPLY_CHAIN` | 行业、证券 | 外部事件沿产业链传播 |
| `AGGREGATE` | 全部 | 各风险分量的可解释聚合 |

### 4.2 标签不是“最高点”

不使用“是否卖在最高点”作为标签。历史风险标签采用：

- 未来 1/5/20/60 日最大回撤；
- 未来实现波动率及其历史分位；
- 未来相关性、市场广度或流动性恶化；
- 行业相对市场的未来跑输；
- 事件发生后的窗口风险；
- 绝对阈值与历史分位相结合。

建议初始研究候选：

- 市场 20 日显著风险：未来最大回撤进入历史最差 10%，并满足绝对跌幅下限；
- 行业 20 日显著风险：未来最大回撤或相对跑输进入历史最差 10%，并满足绝对下限；
- 极端风险：进入历史最差 5%；
- 最终绝对阈值由 Phase 1 的规则基线研究和 Phase 4 的模型校准使用真实历史分布确定，不在 Phase 0 写死。

### 4.3 风险事件按 Episode 评估

连续多个高风险日属于一个风险 Episode，而不是多次成功预警。Episode 至少记录：

- 风险开始；
- 首次警报；
- 风险峰值；
- 风险解除；
- 首次警报到风险发生的提前量；
- Episode 内最高概率和严重程度；
- 是否发生误报、漏报或迟报。

### 4.4 样本外验证

所有需要拟合、调参或选择阈值的逻辑必须：

- 使用时间顺序切分；
- 使用 Walk-forward；
- 对重叠标签使用 Purge/Embargo；
- 防止财务修订、行业成分、公告时间和全球时区泄漏；
- 单独报告不同市场阶段；
- 与简单规则基线比较；
- 报告失败区间，而不只报告总体平均值。

## 5. 阶段治理

### 5.1 严格阶段门禁

每个阶段的状态：

```text
PLANNED
  → IMPLEMENTING
  → VERIFYING
  → ACCEPTANCE_PENDING
  → ACCEPTED
```

只有 `ACCEPTED` 才允许启动下一阶段功能实现。

若阶段未达到门槛：

- 继续修复当前阶段；
- 缩小当前阶段范围并重新确认；
- 或明确记录无法达成及原因；
- 不通过新增更复杂模型掩盖数据或定义缺陷。

对于“验证增量价值”的阶段，严谨的负面结论也可以是阶段成果。例如全球某类数据、机器学习模型或事件 Feature 未稳定优于既有基线时，应当记录“不晋级”，保留已验收基线，并由用户确认是否结束该阶段。阶段完成不等于强制把所有尝试过的复杂能力投入核心风险计算。

### 5.2 每阶段交付

以下是完整风险能力阶段的标准交付，根据各阶段范围选择：

1. 数据覆盖和质量报告；
2. Feature/规则/模型版本清单；
3. API 或数据契约；
4. 自动化测试；
5. 历史回放或样本外验证；
6. Cthulhu 可见页面；
7. 运维与失败状态说明；
8. 阶段验收报告；
9. 下一阶段是否放行的明确结论。

Phase 0 是数据准备阶段，明确简化为：

- 实际可运行的下载、写入、回填和调度；

- 简单验收结论。

Phase 0 不要求 Feature/模型清单、Cthulhu 页面或大型质量报告。

### 5.3 原始数据蓄水例外

以下工作从 Phase 0 即可开始，并持续贯穿所有阶段：

- 保存全球市场原始日线/快照；

- 保存来源发布时间、抓取时间、修订时间；
- 保存供应商响应和接口版本；
- 监控数据源变更、限流、失效和许可。

这些工作不包括 Feature、模型、风险聚合或 UI 功能，因此不视为提前开始后续阶段。

## 8. Phase 1：国内 A 股市场风险基线

### 8.1 目标

建立不依赖全球数据、不依赖 LLM、不依赖机器学习的国内市场风险基线，支持 `PRE_OPEN` 和 `POST_CLOSE`，输出 1/5/20/60 日风险状态。

它是后续所有复杂能力的比较基准，不能被跳过。

### 8.2 所需数据

首版必须：

- 上证、沪深300、中证500、中证1000、创业板、科创等代表指数；
- A 股不复权日线及稳定证券身份；
- 质量合格的成交量和成交额。

历史股票池、上市/退市、停牌、ST、涨跌停、复权、行业、融资和衍生品数据改为增量能力。数据未通过质量门禁时，禁用对应 Feature，不阻塞最小市场风险基线。

### 8.3 初始 Feature

首版核心：

- 指数趋势与均线距离；
- 趋势斜率；
- 5/20/60 日实现波动率；
- 短期/长期波动率比；
- 波动率变化与加速度；
- 指数回撤和极端收益；
- 上涨/下跌家数；
- 高于 MA20/MA60 的股票比例；
- 创新高/创新低比例；
- 市场成交额及历史分位；
- 横截面离散度、相关性和下行相关性；
- 数据质量和每日有效证券覆盖。

数据可用后再增加：

- 涨跌停、ST 和停牌结构；
- 换手率；
- 行业收益集中度；
- 大盘/小盘、价值/成长风格分化；
- 融资、衍生品和其他流动性指标。

### 8.4 各服务工作

| 服务 | 本阶段工作 | 产出/供给 |
|---|---|---|
| Artemis | 扩展 bars、security universe、industry 等 PhoenixA Provider；计算国内市场 Feature | 版本化市场 Feature |
| PhoenixA | 支持 `market` 类型的 Feature/结果持久化和查询；提供历史股票池与 bars 聚合所需 API | 市场 Feature、风险结果 API |
| Feature Platform | 新增经过评审的 `market` 主体；提供 PIT 运行、回填、血缘和质量标记 | 市场 Feature Snapshot |
| Aegis | 实现稳健统计和规则基线；构建风险 Episode；生成多期限风险状态、驱动和置信度 | Domestic Risk Baseline v1 |
| Atlas | 不进入核心计算 | 无阻塞依赖 |
| Cronjob | 编排盘前、盘后 Feature 和风险任务；保证截止时间和幂等 | 日频风险调度 |
| Cthulhu | 建设国内市场风险总览、历史时间线、驱动拆解、数据质量和版本页 | 用户可见风险基线 |

### 8.5 本阶段产出契约

Aegis 为其他服务提供：

- 当前市场风险 Assessment；
- 按期限拆分的风险分量；
- 历史风险时间线；
- 风险 Episode；
- Top Drivers；
- 数据和计算置信度；
- Feature/规则版本血缘。

不提供：

- 买卖结论；
- 仓位限制；
- 个股风险；
- 全球冲击解释。

### 8.6 本阶段完成后用户能看到

- A股盘前和盘后风险状态；
- 1/5/20/60 日风险并列展示；
- 趋势、广度、波动、流动性、相关性、集中度的独立变化；
- 某次风险提升由哪些指标驱动；
- 历史危机区间回放；
- 当前数据是否完整；
- 当前结果来自哪个版本。

### 8.7 验收门槛

进入 Phase 2 前必须：

1. 同一数据快照和版本可重复得到相同结果；
2. 盘前/盘后截止时间无未来泄漏；
3. 历史股票池、停牌和复权处理通过抽样审计；
4. 所有风险状态能追溯到具体 Feature；
5. 基线在多个历史阶段完成回放；
6. Episode 评估能区分提前、迟报、漏报和误报；
7. Cthulhu 不显示无法解释的单一分数；
8. 形成 Domestic Baseline 验收报告；
9. 用户确认国内基线可以作为下一阶段比较对象。

## 9. Phase 2：全球市场风险与 A 股传导

### 9.1 目标

识别全球风险偏好、全球科技/半导体周期和区域市场变化如何被 A 股吸收或放大，并验证全球数据是否对国内基线产生稳定的样本外增量。

### 9.2 所需数据

#### 市场和行业

- 美国：宽基、成长、科技、半导体代表指数或合规代理；
- 韩国：宽基、成长和半导体/存储产业代理；
- 台湾：宽基、晶圆代工和电子供应链代理；
- 日本：宽基、半导体设备和材料代理；
- 香港：宽基、科技和与 A 股互联的风险代理；
- 主要科技公司价格、业绩或资本开支数据，仅在授权和历史可用时使用。

#### 宏观和风险偏好

- 美国国债收益率和期限结构；
- 美元和人民币汇率；
- 全球波动率；
- 商品和产业周期代理；
- 必要的信用和流动性代理。

每条数据必须包含：

- 原市场交易日；
- 原始时区；
- 开闭市时间；
- 实际可获得时间；
- 抓取时间；
- 修订状态；
- A股 `PRE_OPEN/POST_CLOSE` 是否可用。

### 9.3 风险分解

```text
A股市场风险
  = 国内脆弱度
  + 全球共同冲击
  + 区域市场传染
  + 国内吸收/放大效应
  + 不确定性
```

全球输入不能使用静态永久权重。至少评估：

- 滚动相关性和下行相关性；
- Lead/Lag 稳定性；
- 不同风险状态下的条件关系；
- 全球冲击发生时国内估值、广度、流动性是否脆弱；
- 关系失效时是否降权或拒绝判断。

### 9.4 各服务工作

| 服务 | 本阶段工作 | 产出/供给 |
|---|---|---|
| Artemis | 接入全球市场、利率、汇率和风险偏好数据；保存不可变原始快照；标准化交易时段 | 全球 ODS 数据和质量结果 |
| PhoenixA | 建立全球 Instrument/Session/Observation 的治理和查询能力；保存 availability 时间 | 全球数据 API |
| Feature Platform | 支持全球市场输入和严格滞后 Feature；禁止同日未来市场数据泄漏 | Global Shock Features |
| Aegis | 构建全球冲击、区域传染、国内吸收/放大分量；执行国内-only 与国内+全球对比 | Cross-Market Risk v1 |
| Atlas | 暂不解释离散事件；可提供稳定产业实体映射实验，但不进入核心分数 | 可选映射 |
| Cronjob | 按各市场交易时间和 A 股快照截止时间编排 | 跨时区调度 |
| Cthulhu | 全球风险热图、隔夜变化、传导路径、增量效果和数据时钟展示 | 跨市场风险页面 |

### 9.5 本阶段完成后用户能看到

- A股盘前全球风险快照；
- 美国、韩国、台湾、日本、香港的风险热图；
- 哪个全球市场或宏观变量正在贡献风险；
- A股自身脆弱度是放大还是吸收外部冲击；
- 国内-only 与加入全球后的历史效果差异；
- 某条全球数据在当前快照是否真实可用。

### 9.6 验收门槛

进入 Phase 3 前必须：

1. 所有全球数据通过交易时区和可用时间测试；
2. `PRE_OPEN` 不使用 A 股开盘后才知道的数据；
3. 全球数据覆盖多个风险阶段且缺失模式可解释；
4. 完成国内-only 与国内+全球的样本外增量检验；只有产生稳定增量的全球输入才能晋级；
5. 若某来源没有增量，只允许留作诊断，不进入核心风险聚合；
6. 单个海外市场短期相关性不能被误写为永久因果；
7. 数据中断时 Aegis 能降级到国内基线；
8. 若没有全球输入通过晋级门槛，必须形成负面结论、保留国内基线，并由用户确认是否结束本阶段；
9. Cross-Market 验收报告通过。

### 10.3 所需数据

- 行业和成分股日线；
- 行业 PE/PB、总市值、流通市值；

- Atlas 稳定实体和行业 Crosswalk，可用于解释但不作为事件输入。

### 10.4 初始行业 Feature

- 换手率、成交额和资金集中度；
- 龙头贡献和权重集中度；

- 全球行业冲击敏感度；
- 国内市场风险条件下的放大系数；
- 数据覆盖和成分历史置信度。

进入 Phase 4 前必须：

1. 行业身份和成分历史可 PIT 重建；
2. 不使用当前行业分类回填历史；
3. 行业风险能够拆分市场共同风险和行业特有风险；
4. 核心科技子行业均有足够覆盖和质量状态；
5. 不同子行业使用相同契约但允许不同参数和适用域；
6. 全球映射经过业务审查，不以简单名称匹配代替；
7. Tech Sector Risk 验收报告通过。

## 11. Phase 4：统计与机器学习风险校准

### 11.1 目标

把 Phase 1–3 的规则和 Feature 转换为可校准的多期限风险概率，并建立模型注册、训练、验证、晋级、回滚和失效检测。

### 11.2 初始模型范围

优先评估：

- Logistic Regression；
- 带单调或正则约束的 GBDT；
- 生存分析或危险率模型；
- HMM/状态空间；
- 变化点检测；
- 简单概率集成。

本阶段不默认采用：

- 深度神经网络；
- 端到端 LLM 价格预测；
- 强化学习；
- 无法解释和无法校准的黑盒总分。

### 11.3 所需数据

- Phase 1–3 形成并冻结的风险 Episode 和标签；
- Phase 1 国内市场 Feature；
- Phase 2 全球传导 Feature；
- Phase 3 行业 Feature；
- Feature/标签完整版本和 PIT 快照；
- 训练、验证、测试时间切分；
- 数据质量、缺失和适用域标记。

### 11.4 各服务工作

| 服务 | 本阶段工作 | 产出/供给 |
|---|---|---|
| Artemis | 按版本回填训练 Feature；保证训练和在线同源 | 训练数据快照 |
| PhoenixA | 增加模型元数据、训练运行、验证报告、预测和晋级状态的逻辑存储 | Model/Risk Registry API |
| Feature Platform | 管理 Feature/Label 版本、训练快照和依赖血缘 | 可重现训练输入 |
| Aegis | 训练、Walk-forward、校准、基线对比、模型集成、晋级和回滚 | Calibrated Risk v1 |
| Atlas | 不进入模型，保持独立 | 无阻塞依赖 |
| Cronjob | 编排训练、验证、定期校准和在线推断 | 模型任务调度 |
| Cthulhu | 展示校准曲线、召回、命中、提前量、Episode、基线对比和失败区间 | 模型治理页面 |
| MinIO | 保存不可变模型制品、训练配置和必要报告 | 模型 Artifact |

### 11.5 模型晋级候选门槛

Phase 4 应根据实际基准率最终冻结数值。本阶段初始目标建议为：

- 严重风险 Episode 样本外召回率目标不低于 70%；
- 中位提前量目标不低于 3 个交易日；
- 红色风险命中率相对自然发生率至少提升 3 倍；
- 概率分桶具有可接受校准；
- 加入模型后至少一项核心指标显著优于规则基线，且不能以严重牺牲其他关键指标换取；
- 正常阶段不能长期处于高风险；
- 不同历史阶段分别报告，不能只靠单一危机区间获得优势；
- 数据或分布漂移时能够自动降级回已验收基线。

这些是模型晋级门槛，不是收益或逃顶保证。

### 11.6 本阶段完成后用户能看到

- “未来 20 日显著回撤风险为某个概率区间”，而不只是高/中/低；
- 概率是否经过历史校准；
- 当前采用规则基线还是模型；
- 模型相对国内-only、国内+全球和规则基线的增量；
- 哪些年份、行业或状态下模型表现较差；
- 当前是否发生数据或模型漂移。

### 11.7 验收门槛

进入 Phase 5 前必须：

1. 训练与在线 Feature 同源；
2. 全部训练可由冻结快照重现；
3. 无未来泄漏、标签重叠和行业成分泄漏；
4. 只有在独立样本外优于规则基线的模型才能晋级；
5. 概率校准、漂移和回滚可验证；
6. 未达门槛的模型不得进入正式风险聚合；
7. 若没有候选模型通过晋级门槛，必须明确保留规则基线、记录负面研究结论，并由用户确认是否结束本阶段；
8. Calibrated Risk 验收报告通过。

## 12. Phase 5：Atlas 事件、供应链与影响引擎

### 12.1 目标

引入离散外部事件和产业链传播，使系统能够解释：

> 发生了什么，影响谁，通过哪条产业链路径，在什么期限内产生何种方向和强度的风险。

Atlas 提供结构化影响，Aegis 决定该影响对最终风险概率的增量。

### 12.2 所需数据

- A股、港股和海外公司公告；
- 政策、监管和贸易规则；
- 可信新闻和快讯；
- 全球科技公司财报、指引和资本开支；
- 产品价格、库存、产能和交付；
- 研报和产业资料；
- 原始文件、发布时间、抓取时间、修订时间和来源等级；
- Phase 3 的产业分类 Crosswalk；
- Atlas 产业链实体和关系。

来源优先级：

1. 交易所、公司、监管、政府和统计机构；
2. 授权供应商；
3. 东方财富、AKShare 等补充来源；
4. 二次转载只作候选召回，不作唯一事实。

### 12.3 Atlas 能力扩展

- `EventMention`：单文档中的事件描述；
- `CanonicalEvent`：多个 Mention 对同一现实事件的聚合；
- `EventRevision`：事件随时间变化的版本；
- 事件状态、发生时间、发布时间和可用时间；
- 事件实体、行业、产品、材料和地域链接；
- 影响方向、期限、路径和条件；
- 证据引用和来源等级；
- 市场价格连续信号与离散事件分离；
- 事件去重、冲突和撤回。

### 12.4 各服务工作

| 服务 | 本阶段工作 | 产出/供给 |
|---|---|---|
| Artemis | 采集公告、新闻、政策、海外公司资料和价格信号；保存原文与快照 | Event Source Corpus |
| PhoenixA | 存储 Event/Revision/Impact 元数据、证据引用和风险关联 | Event/Impact API |
| Feature Platform | 接收 Atlas 已发布的数值型影响 Feature；保留文本/JSON 的专用存储边界 | Event Impact Features |
| Atlas | 实现事件三层模型、去重、修订、实体链接和 Impact Engine | 事件与供应链影响 |
| Aegis | 把事件影响与国内脆弱度、全球冲击、行业风险结合；做消融和增量验证 | Event-adjusted Risk |
| Cronjob | 编排采集、抽取、审核、影响计算和风险重算 | 事件流水线 |
| Cthulhu | 事件时间线、证据、产业链路径、影响对象和风险变化 | 事件风险页面 |

### 12.5 边界

Atlas 不允许：

- 仅凭 LLM 自由文本直接提升最终风险到红色；
- 没有 evidence_quote/source/time 的事件进入核心风险；
- 把新闻中的“价格上涨”当成权威市场价格；
- 把多个转载当成多个独立事件；
- 把分析师观点当成已发生事实。

Aegis 必须：

- 区分事件事实、市场反应和基本面实现；
- 对事件 Feature 做增量验证；
- 对低置信度事件降权或仅作解释；
- 保留无事件模型作为回退基线。

### 12.6 本阶段完成后用户能看到

- 事件首次出现和后续修订；
- 来源、原文证据和可信等级；
- 事件涉及的公司、产品、材料和行业；
- 事件沿产业链传播的路径；
- 预计短、中、长期影响方向；
- 事件加入前后风险概率变化；
- 模型认为该事件重要的原因；
- 事件不确定或冲突的明确标记。

### 12.7 验收门槛

进入 Phase 6 前必须：

1. 事件去重、实体链接和证据覆盖通过人工金标集；
2. Event Revision 能重建当时已知状态；
3. 事实、观点、预测和场景严格区分；
4. Impact 路径可追溯；
5. 只有对行业风险产生稳定样本外增量的事件 Feature 才能进入概率聚合；
6. 没有增量但证据质量合格的事件能力只能作为解释层，并须明确标记；
7. LLM 或来源失效时可退回 Phase 4 风险；
8. 若没有事件 Feature 通过风险晋级门槛，必须记录负面结论并由用户确认是否结束本阶段；
9. Event/Impact 验收报告通过。

## 13. Phase 6：个股综合风险

### 13.1 目标

在市场、全球、行业和事件风险均已稳定后，为单只股票输出独立、多期限、可解释风险。

### 13.2 所需数据

#### 价格与流动性

- 不复权/复权行情；
- 成交额、换手率、停牌、涨跌停；
- Beta、下行 Beta、相关性、跳空和流动性；
- 龙虎榜、大宗交易、融资融券等经过验证的数据。

#### 估值与基本面

- PE/PB/PS/PCF 及自身历史、同行分位；
- 收入、利润、现金流、资产负债；
- TTM 和单季度变化；
- 盈利质量、应计、现金转换；
- 杠杆、偿债能力、商誉、减值；
- 业绩预告、业绩快报和分析师预期修订；
- 财务公告和修订的 PIT 时间。

#### 公司行为与事件

- 股权质押；
- 限售解禁；
- 股东和高管增减持；
- 回购；
- 重大合同；
- 停复牌、风险提示、ST 历史；
- Atlas 供应链暴露和事件影响。

### 13.3 个股风险分解

```text
个股风险
  = 市场共同风险
  + 行业共同风险
  + 个股价格/流动性风险
  + 估值压缩风险
  + 基本面恶化风险
  + 公司行为风险
  + 事件/供应链风险
  + 数据与模型不确定性
```

### 13.4 各服务工作

| 服务 | 本阶段工作 | 产出/供给 |
|---|---|---|
| Artemis | 接入并补全个股风险数据；计算估值、质量、流动性和公司行为 Feature | Security Risk Features |
| PhoenixA | 提供个股 Feature、公告、公司行为和风险结果查询 | Security Risk API |
| Feature Platform | 扩展可研究的 security Feature Pack；保持 PIT、版本和行业标准化 | Security Feature Snapshot |
| Atlas | 提供公司实体、产业链暴露、事件路径和证据 | Company Impact Features |
| Aegis | 生成个股各期限和各风险分量；分行业训练或校准 | Security Risk v1 |
| Cronjob | 在市场、全球、行业和事件输入完成后计算个股风险 | 个股风险调度 |
| Cthulhu | 个股风险卡、历史、同行、驱动、事件和数据质量 | 个股风险页面 |

### 13.5 本阶段完成后用户能看到

- 某只股票的 1/5/20/60 日风险；
- 当前高风险究竟来自市场、行业还是公司本身；
- 估值处于自身历史和同行什么位置；
- 盈利质量、杠杆、商誉、质押、解禁等风险；
- 哪个供应链事件影响该公司；
- 风险概率变化及证据；
- 数据不足时为什么不能判断。

### 13.6 验收门槛

进入 Phase 7 前必须：

1. 财务、公告和公司行为严格 PIT；
2. 估值按行业和公司自身历史比较；
3. 银行、保险、证券等特殊行业不套用错误公式；
4. 新股、ST、停牌、退市和流动性极低证券单独评估；
5. 个股模型在行业、规模和上市时间分组下报告效果；
6. 市场/行业/个股风险贡献可相加解释但不重复计算；
7. Security Risk 验收报告通过。

## 14. Phase 7：组合风险聚合

### 14.1 目标

把已验收的市场、行业和个股风险投影到实际持仓，度量组合暴露，不产生交易指令。

### 14.2 所需数据

- 组合和账户身份；
- 持仓证券、数量、成本和快照时间；
- 现金；
- 组合基准；
- 行业和风格暴露；
- 证券相关性和流动性；
- 历史持仓快照；
- 用户授权和敏感数据权限。

持仓可先由人工导入或只读 API 提供。券商自动连接和下单不属于本阶段。

### 14.3 组合风险

- 市场 Beta 和下行 Beta；
- 行业/科技子行业集中度；
- 个股集中度；
- 相关性簇和分散失效；
- 流动性和退出容量；
- 多期限预期尾部风险；
- 历史和情景压力；
- 全球冲击和事件对组合的传播；
- 风险贡献，而非仅组合总分。

### 14.4 各服务工作

| 服务 | 本阶段工作 | 产出/供给 |
|---|---|---|
| Artemis | 不负责持仓；继续提供 Feature | 无新增持仓职责 |
| PhoenixA | 存储受控的 portfolio/position snapshot 和权限审计 | Portfolio Data API |
| Feature Platform | 评审是否增加 portfolio 主体；通用证券 Feature 不复制 | Portfolio Feature Contract |
| Atlas | 提供组合内证券的事件和供应链聚合 | Portfolio Event Exposure |
| Aegis | 聚合市场、行业、证券、相关性、流动性和情景风险 | Portfolio Risk v1 |
| Cronjob | 按持仓快照和风险依赖计算组合风险 | 组合风险调度 |
| Cthulhu | 组合风险总览、贡献、集中度、情景和数据时间 | 组合风险驾驶舱 |

### 14.5 本阶段完成后用户能看到

- 组合风险来自哪些市场、行业和股票；
- 是否过度集中于半导体、AI 硬件等共同风险；
- 表面多只股票是否实际高度相关；
- 全球或供应链事件会影响组合的哪些部分；
- 在不同风险情景下组合可能如何变化；
- 持仓数据截至什么时间；
- 不显示自动买卖或减仓数量。

### 14.6 验收门槛

进入 Phase 8 前必须：

1. 持仓和现金可对账；
2. 组合风险贡献与底层证券结果一致；
3. 权限、日志和敏感数据保护通过审计；
4. 相关性、流动性和情景计算通过已知组合测试；
5. 无券商写入和下单能力；
6. Portfolio Risk 验收报告通过。

## 15. Phase 8：生产影子运行与持续治理

### 15.1 目标

将所有已验收能力进入稳定的生产影子运行，持续观察真实风险效果，但仍不自动交易。

### 15.2 各服务工作

| 服务 | 本阶段工作 | 产出/供给 |
|---|---|---|
| Artemis | 数据 SLA、重试、源切换、质量隔离和回填 | 稳定数据与 Feature |
| PhoenixA | 容量、归档、查询 SLA、备份和恢复 | 稳定风险数据网关 |
| Feature Platform | 运行监控、版本发布、回滚、依赖治理 | Feature 生产保障 |
| Atlas | 抽取/事件质量、LLM 漂移、证据和人工复核 | Atlas 生产保障 |
| Aegis | 在线推断、漂移、校准监控、基线回退、事后 Episode 评估 | 生产风险服务 |
| Cronjob | 完整 DAG、补偿、超时、重跑和阶段隔离 | 稳定调度 |
| Cthulhu | 当前状态、任务健康、数据时钟、模型漂移、风险历史和通知 | 生产风险驾驶舱 |

### 15.3 生产运行要求

- 每次评估保存完整血缘；
- 数据迟到后支持可审计重算；
- 新模型只通过 Champion/Challenger 晋级；
- 规则和模型均可回滚；
- 全球或 Atlas 失效时分级降级；
- 数据质量失败优先显示 `UNKNOWN`；
- 持续统计误报、漏报、迟报和提前量；
- 定期重新校准但不自动无审核替换模型；
- 风险通知只描述风险，不包含交易动作；
- 所有结果带“风险判断并非收益保证”的产品说明。

### 15.4 本阶段完成后用户能看到

- 今日盘前、盘后所有风险快照是否准时完成；
- 每个输入数据源和服务的健康状态；
- 当前使用的 Feature、规则和模型版本；
- 风险概率、原因和置信度；
- 一段时间后的真实命中、漏报、提前量和校准；
- 当前是否处于降级模式；
- 某次历史判断当时究竟使用了哪些数据。

### 15.5 最终验收门槛

Phase 8 完成必须：

1. 连续影子运行达到约定观察期；
2. 数据和任务 SLA 达标；
3. 风险结果可重现；
4. 漂移、降级和回滚演练通过；
5. 线上 Episode 指标与历史验证没有不可解释的大幅偏离；
6. 未发生风险结果直接触发交易；
7. 形成生产验收报告。

完成 Phase 8 后，其他策略服务才可以申请把风险结果作为输入。策略接入必须另写设计和验收，不属于本文自动授权范围。

## 16. 跨阶段数据优先级

### 16.1 P0：必须拥有

- A股股票和指数日线；
- 历史股票池；
- 交易日历、复权、停牌；
- 申万行业成分和行业行情；
- 价格、成交、换手；

### 16.2 P1：全球传导必须补充

- 美国、韩国、台湾、日本、香港；
- 科技和半导体代理；
- 利率、汇率、全球波动率；
- 交易时段和可用时间。

### 16.3 P2：行业和个股风险

- 融资融券；
- 股权质押；
- 限售解禁；
- 股东和高管增减持；
- 商誉和减值；
- 停复牌和 ST 历史；
- ETF/基金持仓和行业配置；
- 经过验证的资金和拥挤数据；
- 期权隐含波动率和期货持仓。

### 16.4 P3：事件与供应链

- 公告、政策和监管；
- 国内外公司财报和指引；
- 新闻和快讯；
- 产品价格、库存、产能和资本开支；
- 原始文档和不可变证据；
- Event Revision 所需时间字段。

### 16.5 数据源原则

- 官方来源优先；
- 授权商业来源其次；
- 东方财富、AKShare 等作为补充和交叉验证；
- 对只返回近期数据的接口，从接入第一天保存原始快照；
- 不允许网页当前可见等同于可稳定回测；
- 数据许可、访问频率和再分发边界在接入前确认。

## 17. 跨阶段质量红线

任意阶段触发以下条件时，不得继续晋级：

1. 未知值被静默转换为零；
2. 使用当前行业成分回填历史；
3. 使用事后修订财务但未保存当时版本；
4. 使用 A 股截止时间之后的全球数据；
5. 训练集和测试集随机打乱时间；
6. 只在一次危机上有效；
7. 模型概率未校准却作为概率展示；
8. LLM 结论没有证据；
9. 数据源失效后仍显示绿色低风险；
10. 风险结果无法追溯 Feature 和模型版本；
11. 在风险服务中加入买卖、仓位或订单逻辑；
12. 为了进入下一阶段而降低既定质量门槛，却未重新取得批准。
