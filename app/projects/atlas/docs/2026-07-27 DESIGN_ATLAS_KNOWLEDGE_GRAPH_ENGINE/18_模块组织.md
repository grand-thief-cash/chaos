### 18.4 配置边界

工程骨架参考 Artemis 的约定：`main.py` 支持 `-c/--config` 与 `-e/--env`，`ConfigManager` 加载 `config/config.yaml` 及 `config-{env}.yaml` 覆盖文件，HTTP 入口集中在 `api/http_gateway`，外部客户端集中在 `core/clients`。Atlas 不机械复制 Artemis 的 Engine/Service 业务分层，仍保留 `knowledge_production / knowledge_store / intelligence / application` 四个领域边界。

程序运行参数放入 `config.yaml`，`prompt_profile_key` 到具体 Prompt 实现的路由单独放入 `report_prompt_mapping.yaml`。报告类型是否启用由 Published Semantic YAML 单独决定。

`semantic_seed.yaml` 只用于第一次 BOOTSTRAP_DISCOVERY 的基础枚举，不作为生产运行时配置。生产和测试必须读取明确版本的 `atlas-semantic-vNNNN.yaml`。

示例：

```yaml
env: development

server:
  host: 0.0.0.0
  port: 18400
  access_log: false

dept_services:
  phoenixA:
    host: 127.0.0.1
    port: 18085
    scheme: http

minio:
  endpoint: 127.0.0.1:9000
  bucket: research-report

llm:
  extraction:
    provider: openai_compatible_pdf
    base_url: http://127.0.0.1:11435/v1
    model: qwen3-14b-q4_k_m
    timeout_seconds: 900
    temperature: 0
    maximum_output_tokens: 16384
    structured_output_mode: json_object
  agent:
    provider: ollama
    base_url: http://127.0.0.1:11434/v1
    model: qwen3-14b-q4_k_m
    api_key_env: OLLAMA_API_KEY
    timeout_seconds: 300
    temperature: 0
    maximum_output_tokens: 8192
    structured_output_mode: json_schema

taxonomy:
  canonical_seed_scheme: SW2021
  schemes:
    SW2021:
      source: amazing_data
      taxonomy: swhy
      market: zh_a
    EastMoneyIndustry:
      source: eastmoney
      taxonomy: industry
      market: zh_a
    EastMoneyConcept:
      source: eastmoney
      taxonomy: concept
      market: zh_a

engine:
  knowledge_engine:
    pipeline_version: atlas-kg-v1
    research_report_source: eastmoney
    poll_batch_size: 20
    llm_concurrency: 1
    maximum_total_attempts: 3
    semantic_config_path: config/semantic/atlas-semantic-v0001.yaml
    prompt_mapping_path: config/report_prompt_mapping.yaml

```

`llm.extraction` 与 `llm.agent` 是两个明确能力边界。Ollama 的
OpenAI-compatible Chat Completions 用于结构化文本 Agent，但不假设它支持
PDF file content；Whole-PDF 抽取必须指向实际支持 PDF 输入的独立 endpoint。
未来切换 DeepSeek 等付费模型时使用 `openai_compatible` provider 和
`api_key_env`，不修改上层 Orchestrator。

实体接受阈值、未知 Predicate 不投影、Crosswalk 全覆盖、事实图 Assertion
allowlist、最大 Query tool call 等属于 Phase 1 的安全不变量，当前固定在对应
程序化模块中，不为部署者暴露可以误关的 YAML 开关。只有当真实运行证明需要
按环境调优时，才把数值阈值提升为配置；不能把“允许任意 Cypher/写库”变成配置。

Phase 1 的 PDF 行为不是配置能力：程序固定从 MinIO 读入字节，使用 pikepdf 在内存中重存以解除 owner permission，随后直接把同一内存缓冲交给 Whole-PDF 模型调用；不创建临时副本、不提供 chunking 开关，也不保留另一个 PDF 对象。

Prompt Profile 路由示例：

```yaml
prompt_profiles:
  company-research-v1:
    template: prompts/research-extraction-v1.jinja2
    version: research-extraction-v1
    extract_relations: true
    extract_quantified_claims: true
    extract_analyst_views: true
```

Artemis report type → `enabled_for_production` → `prompt_profile_key` 的映射只存在于 Published Semantic YAML。`report_prompt_mapping.yaml` 只解析 `prompt_profile_key`，不允许再次定义某类报告是否启用。

`graph_repository` 只调用 `phoenixa_client` 提供的受控 Graph Projection/Query API；Atlas 中不配置 Neo4j URI、用户名、密码或 Bolt Driver。

配置能控制运行参数，但以下变化必须升级版本，不能只改 YAML 后覆盖旧结果：

- Entity Type 语义变化。
- Assertion Type 语义变化。
- canonical predicate 的方向或含义变化。
- Claim Schema 变化。
- Graph Projection 语义变化。
- Prompt 导致抽取含义发生明显变化。
